# Command-line performance reproduction

[中文版](README.zh-CN.md)

This group reproduces execution performance for the paper's command-line workloads. Timed programs and shared libraries come from the matching `evaluations/1-libs` installations. The official native FFmpeg under `vcpkg/installed/arm64-linux` only prepares media inputs and is never timed.

## 1. Current workloads

The repository provides all 8 workloads used by the paper:

| No. | Workload | Input | Timed operation | Recipe |
|---:|---|---|---|---|
| 1 | FFTW 3.3.10 | `3072x3072` complex 2D problem | Planning and forward transform | `fftw/` |
| 2 | zstd 1.5.7 | 100 copies of deterministic 64 MiB data | Level 3 single-worker compression | `zstd/` |
| 3 | zlib 1.3.2 | 5 copies of deterministic 64 MiB data | `minizip -9` | `zlib/` |
| 4 | OpenSSL 3.0.22 | 3 copies of a deterministic 256 MiB file | SHA-256 digest | `openssl/` |
| 5 | FFmpeg with libmp3lame | Fixed WAV excerpt looped 7 times | MP3 encoding | `ffmpeg-mp3lame/` |
| 6 | FFmpeg with libfdk_aac | Fixed WAV excerpt looped 10 times | AAC encoding | `ffmpeg-fdk-aac/` |
| 7 | FFmpeg with libvorbis | Fixed WAV excerpt looped 7 times | Vorbis encoding | `ffmpeg-vorbis/` |
| 8 | FFmpeg with libx264 | Fixed Y4M video excerpt | H.264 encoding | `ffmpeg-x264/` |

## 2. Comparison paths

Each workload runs 9 paths by default:

1. `native`
   - Native AArch64 program and shared libraries.
2. `qemu`
   - x86-64 program under pure QEMU emulation.
3. `blink`
   - x86-64 program under pure Blink emulation.
4. `box64`
   - x86-64 program under pure Box64 emulation.
5. `fex`
   - x86-64 program under pure FEX emulation.
6. `qemu-hecate`
   - QEMU integrated with Hecate and calling native AArch64 libraries.
7. `blink-hecate`
   - Blink integrated with Hecate and calling native AArch64 libraries.
8. `box64-hecate`
   - Box64 integrated with Hecate and calling native AArch64 libraries.
9. `fex-hecate`
   - FEX integrated with Hecate and calling native AArch64 libraries.

Version consistency follows these rules:

- Native and x86-64 programs come from the same `1-libs` recipe and upstream version.
- Hecate and its corresponding pure emulator execute the same x86-64 CLI.
- Hecate host libraries come from the same recipe's AArch64 installation.
- Every path uses identical input.
- The instrumented `box64-callback-track-ae` never participates in performance evaluation.

## 3. Prepare inputs

Prepare all deterministic and media inputs once:

```bash
./evaluations/2-cli-benchmarks/_common/prepare-inputs.sh
```

Inputs are:

1. Deterministic data
   - Generated by Python.
   - Used by zlib and zstd.
2. Media data
   - The source is pinned by [`_inputs/media-source.json`](_inputs/media-source.json).
   - `yt-dlp` downloads the public video.
   - Native FFmpeg extracts WAV and Y4M excerpts outside the timed region.

`_inputs/manifest.json` records each filename, byte size, SHA-256, source, and derivation. Downloads and derived binaries are ignored by Git. If Ubuntu's packaged `yt-dlp` cannot read current YouTube metadata, set:

```bash
YT_DLP=/absolute/path/to/yt-dlp \
  ./evaluations/2-cli-benchmarks/_common/prepare-inputs.sh
```

## 4. Install workloads

Install shared tools and every workload prerequisite without measuring:

```bash
./evaluations/2-cli-benchmarks/run-all.sh --install-only
```

This command:

1. Invokes `evaluations/install-tools.sh`.
2. Invokes `run.sh --install-only` for all 8 workloads.
3. Reuses native, guest, Hecate, and thunk state installed by `1-libs`.

`--install-only` does not download media or generate workload inputs. A timed run invokes the preparation script from Section 3 if inputs are missing.

## 5. Run every workload

Run all 8 workloads:

```bash
./evaluations/2-cli-benchmarks/run-all.sh
```

Defaults are:

- 5 repetitions per path.
- A cutoff of 20 times the native median for every non-native path, capped at 100 seconds.
- A path reaching its cutoff is terminated and marked as excluded from Figure 17. It is not counted as a failure or a performance ratio.
- Raw wall-clock time for every repetition, not only a summary.

Override repetitions or lower the hard timeout with:

```bash
REPETITIONS=7 TIMEOUT_SECONDS=80 \
  ./evaluations/2-cli-benchmarks/run-all.sh
```

`TIMEOUT_SECONDS` cannot raise the 100-second hard limit.

## 6. Select paths

Run selected paths only:

```bash
./evaluations/2-cli-benchmarks/run-all.sh \
  --lanes native,qemu,qemu-hecate
```

Valid lane names are:

- `native`
- `qemu`
- `blink`
- `box64`
- `fex`
- `qemu-hecate`
- `blink-hecate`
- `box64-hecate`
- `fex-hecate`

After changing lanes, repetitions, timeout, devkit, or emulator paths, existing batch state is not mixed with the new configuration. The runner asks for `--restart` to begin a new batch.

## 7. Batch execution and recovery

Controller state is stored under:

```text
.work/evaluations/2-cli-benchmarks-batch/<mode>/
```

Batch behavior is:

- A failed workload does not prevent later workloads from running.
- Repeating the same command skips successful items.
- Failed, interrupted, and pending items are retried.
- `--restart` moves old state into `history/` and begins again.
- After a workload recipe is added or removed, the controller rejects the old plan and requires `--restart`.
- `--plain` disables the progress display fixed to the bottom of the terminal.
- An interactive terminal shows the 3 most recent results, the current workload, and overall progress.

## 8. Run one workload

Each `<workload>/run.sh` is its public entry point. For example:

```bash
./evaluations/2-cli-benchmarks/fftw/run.sh
REPETITIONS=1 ./evaluations/2-cli-benchmarks/zstd/run.sh \
  --lanes native,qemu,blink,qemu-hecate
```

An item README defines:

1. Input format and size.
2. Complete workload arguments.
3. Emulator-specific options.
4. Output validation.
5. Current limitations.

## 9. Results and evidence

Evaluator results are written to:

```text
evaluations/2-cli-benchmarks/<workload>/results/<run-id>/
```

Each workload preserves at least:

1. Complete commands for every lane.
2. Exit status and wall-clock time for every repetition.
3. Input byte size and SHA-256 where the workload consumes a file.
4. Library package, CLI, and emulator versions.
5. Devkit and Hecate component identity.
6. Timeout, repetition count, and selected lanes.
7. Median and range recomputed from raw samples.

Preview and remove evaluator results with:

```bash
./evaluations/2-cli-benchmarks/delete-all-results.sh --dry-run
./evaluations/2-cli-benchmarks/delete-all-results.sh
```

Cleanup never removes `_inputs/`, shared vcpkg downloads, or package caches.
